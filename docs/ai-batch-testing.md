# AI 批量问题回归（2026-10-20）

用户授权使用已配置的真实模型测试并修复。业务查询只读；会话和权限测试数据仅写入 `mini_mfg_test`，开发库不灌测试会话、不执行采购/领料/入库/发货。没有修改依赖、数据库结构、业务记账规则或参考项目。

## 发现与修复

| 问题 | 根因 | 调整 |
|---|---|---|
| 原料仓提示未找到 | 公开资料搜索按名称/编码字面匹配，实际名称为“演示·电脑零部件仓” | 字面匹配为空时，用有限仓库词表查真实候选；原料→原料/零部件，成品→成品/整机；多候选仍须选择，不硬编码ID |
| 完整仓名、编码查不到 | 正则丢失“·”，也把“零部件仓库存”中的“库”吞进仓名；未识别引号内仓库编码 | 保留名称分隔符，区分“仓库”与“仓库存”，支持`仓库「编码或名称」` |
| 仓库与物料名称不能同时使用 | 一次仅支持解析一个对象 | 顺序解析两个对象；澄清保存已解析范围，后端重新核验候选 |
| 补充正确ID/名称仍重复问 | 旧失败查询优先于新输入 | 明确标注的仓库/物料/工单ID可纠正旧范围；新名称替换旧查询；裸“选择ID”仍核对候选 |
| 缺货、整机还没入库被问销售日期 | 路由只识别少数固定词 | 识别缺货、还没入库、尚未入库等只读表达 |
| 最近30天卖得怎么样被问指标 | 销售入口仅识别销售/订单/sales | 增加卖得/卖了/卖出等销售表达，仍走真实模型规划和反思 |
| 补充期间改问销售仍查库存 | 旧待澄清任务无条件接管新问题 | 新销售/客户/利润问题退出旧库存补充路线 |
| 查询完成后“那成品仓呢”丢失任务 | 成功上下文仅存domain | 保存已验证的操作及范围；更换仓库时重新查询，保留原物料过滤 |

所有身份仍来自用户明确ID或Java候选；权限、服务认证、能力上限和库存事实来源不变。通用自然语言物料过滤仍不猜测：如“原料仓的CPU库存”无法完整解析时要求`物料「CPU」`或物料ID，不静默返回全仓。

## 实际结果

- 首轮26项：15项达到预期，11项未达到预期；原始问题、回答和SSE事件保存在忽略目录 `output/ai-evaluation/operations-before.json`。
- 修复后扩展为35项：**35项通过**。其中32项经真实Java HTTP/SSE、LangGraph和MySQL，1项匿名401；另2项为Agent范围真实网络故障探针，不能算Java代理端到端故障验收。
- 完整销售、销售口语、空数据、库存切换销售、利润澄清后改问销售共5项实际调用配置中的DeepSeek模型，经历Planner/Executor/Analyzer/Reflection/Reporter；模型故障探针额外调用真实接口的不存在模型。库存、缺料和排行按既定确定性分支执行，不将这些场景宣称为LLM推理测试。
- 测试库有大量历史测试仓库，6个别名场景正确返回多个候选，评测器明确模拟用户选择演示仓库ID后核对结果。首轮“未找到”不会通过这项检查；没有为提高通过率让Agent擅自选第一个候选。
- 销售金额对照独立订单明细SQL；排行对照独立分组结果；库存核对完整返回范围、余额及阈值；缺料核对确认快照和当前余额后独立相减；待入库核对单据ID。不是只检测回答非空。
- Python单元/图测试140项通过（1项既有Starlette/AnyIO弃用警告）；Java单元26项、AI相关真实MySQL集成19项通过。
- 真实批量结果含每题完整回答与事件，保存在 `output/ai-evaluation/operations-verified.json`，不含请求凭据或HTTP头。

35项包括：销售2、客户/商品排行2、利润边界、空数据、库存名称/编码/ID/口语/组合范围11、待入库3、工单缺料2、历史库存与写操作拒绝、未知仓库、ID纠正、名称纠正、切换销售、工单/仓库补充、完成后换仓追问、利润改销售、匿名401、真实模型失败、真实工具网络失败。逐项以JSON中的case为准。

## 复跑命令

仅使用本项目私密环境变量，命令不打印凭据。真实模型会产生API调用。先停止自己创建的18081测试后端再打包，Windows运行中的JAR会锁文件；首次本次打包曾因此失败，停止测试进程后重新verify成功。

```powershell
. ./scripts/Import-LocalEnvironment.ps1
cd backend
./mvnw.cmd -B -P integration '-Dit.test=AiOperationsIntegrationTest,AiIntegrationTest,SalesDimensionsIntegrationTest,SalesAnalyticsIntegrationTest' verify
cd ..
$env:PYTHONPATH="$pwd/agent"
./agent/.venv/Scripts/python.exe -m pytest agent/tests -q
```

终端1（隔离测试后端）：

```powershell
$env:MFG_AI_AGENT_URL='http://127.0.0.1:8092'
./scripts/Start-E2eBackend.ps1
```

终端2（隔离Agent）：

```powershell
. ./scripts/Import-AiEnvironment.ps1
$env:AI_ERP_BASE_URL='http://127.0.0.1:18081'
./agent/.venv/Scripts/python.exe -m uvicorn app.main:app --app-dir agent --host 127.0.0.1 --port 8092
```

终端3：

```powershell
./scripts/Test-AiBatch.ps1 -Label operations-verified
```

批量入口核验测试库配置、18081的test进程和8092的本项目Agent；任一问题失败退出码非零。需要测试库已有演示资料与待领料工单；不自动灌数、不清理业务库。每次追加测试会话，适合显式回归，不在应用启动时运行。

## 验证边界

本轮是接口级真实链路验收，未重新执行浏览器UI验收，未宣称覆盖所有自然语言表达。利润、历史库存、自由SQL、自动写业务操作仍不支持。模型/API失败如实报错；本次通过不代表外部服务永远可用。重名对象澄清是正确行为，不能算模型没有能力。
