# AI第6阶段：有界会话条件与澄清恢复

2026-10-21后续[模型循环改造](ai-model-loop.md)沿用本契约，澄清由模型提出conditions、代码校验后持久化；额外允许最多400字符、已脱敏的最近失败问题retryRequest供显式重试。新问题或成功后清除，计入4096字节上限；不保存整段历史或工具数值。下文“旧问题不原样转发”仍适用于历史迁移字段originalMessage，retryRequest是本次新增的有界故障恢复字段。

沿用 MySQL 的 `ai_conversation.context_json` 与 `ai_message`，没有新表、向量数据库、依赖或业务工具。这里只保存查询条件与待澄清状态，不是完整长期记忆，也不是 LangGraph Checkpoint：节点、工具响应和执行位置不会跨请求恢复。

## 保存与恢复

Java `AiContext` 与 Python `context.py` 双重白名单过滤，版本1，UTF-8最多4096字节。允许日期（上海时间、结束不包含）、销售口径、客户/商品维度与后端ID、最近确认的客户/商品ID、仓库/物料/工单ID、排行数量、待澄清类型、必要名称查询及已确认选项。未解决的对象查找最多保存两个后续条件。

不保存工具数值、凭据、授权票据、联系人、候选列表或完整旧问题。必要名称/编码最多100字符，过滤明显手机号、邮箱和密钥格式；这不是对任意敏感文本的完整分类。聊天消息仍按既有历史保存，用户应避免输入秘密；不会从全部聊天提取自动记忆。旧上下文原问题仅转换为允许的日期表达式、维度和必要名称，不再原样转发。

每次请求只发送本条问题、过滤后的条件与本轮短期授权，不重复发送全部历史。最近会话最多50条，详情最多200条消息；容量不足以保存下一轮时要求新建会话。正常一问一答最多100轮，取消或失败也可能占用容量。

“那上个月呢？”沿用指标与已确认对象，修改日期；“只看刚才那个客户”只使用最近确认的客户ID，无法唯一确定则澄清。指代与新日期/指标同句时保留新条件。排行前N名条件随日期追问保留。

“换成原料仓”在库存上下文中重新解析仓库，保留已确认或尚待选择的物料，不静默扩大成全仓。销售上下文不能把仓库当作未支持的销售筛选，先询问库存查询类型。显式新对象ID覆盖旧对象及旧名称限制；真正的候选选择必须重新查询并验证ID。重名、无候选或截断时继续澄清。

Context阶段展示“沿用/修改”的具体条件；页面展示服务器当前条件。范围变化后重新调用工具，不沿用上轮数值。切换销售与库存时移除不适用的活动条件；库存不继承销售日期。

## 页面与失败

URL使用 `?conversation=后端ID`，只接受正整数字符串；刷新后由归属校验接口读取原会话、条件及未完成澄清。不依赖 localStorage 保存上下文，浏览器不能提交替代resume。新会话清除URL条件。

Java接收过滤后的Context阶段即保存条件，终态保存结果状态。模型失败、断流、取消保留最近保存的条件；重试是新查询，不宣称从原节点继续。未到达保存阶段的内容可能需要重新补充。刷新时仍在运行的任务显示运行状态并允许取消，不伪造恢复执行。

## 授权与验证

会话列表、详情、继续与取消按固定租户和用户隔离；其他用户访问返回404。短期授权同时核验会话、运行、租户与所有者。每次工具调用重新取得当前用户状态/权限并检查对应业务权限及对象范围。存储的ID和已确认选项不是授权，权限撤销、用户停用后不能凭历史继续查询。会话登录、CSRF与默认拒绝保持不变。
