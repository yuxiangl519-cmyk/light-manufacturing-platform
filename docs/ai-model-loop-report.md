## 发现并修复

前三轮及第四轮中间验收分别为8/11、10/11、9/11、10/11；最后修复后为11/11。各轮失败原因、耗时及已知调用统计保留在JSON，未以最后一次成功覆盖失败记录。

- 新ID覆盖旧ID，重名选择须重新核验；选择已消失时不替换成其他唯一对象。报告记录对象范围，不能用旧仓库结果回答本轮明确的客户ID问题。
- 澄清保存白名单conditions，缺日期仍保留客户名称/指标，刷新补仓继续原操作。模型对已齐备条件重复澄清会收到反馈纠正，执行器不会代替模型直接调用工具。
- 模型无效报告引用最多反馈纠正两次；利润/指标澄清中的“建议改查销售”不当作用户已确认。兼容模型使用warehouse等澄清标签，但统一保存为既有operation/entity类型。
- 模型调用尚未成功就失败时，保存最多400字符的脱敏最近问题供显式重试；成功后清除。等价安全模板补查成功按证据项消除失败，未补齐的错误仍不能发布完整报告。

5轮浏览器已记录终态合计119次模型请求、114份usage共338886 token；另有2次只调用真实提供方、无工具/无数据库的协议定位探针，返回usage合计4401 token。取消和拒绝响应的缺失仍未补造；这些是可核对的已知部分，不是整个开发过程的完整消费。
