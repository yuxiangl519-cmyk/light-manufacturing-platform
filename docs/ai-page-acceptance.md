沿用Vue分析会话页、现有组件、Fetch SSE与MySQL历史。没有新业务工具、依赖、复杂BI大屏、向量库或完整Checkpoint。实际执行结果另见[本轮报告](ai-page-report.md)，本说明不是检查通过的证据。

2026-10-21后续改造已切换为[模型驱动循环](ai-model-loop.md)：所有分析问题先由模型决策，下面的浏览器成功流程必须显式开启Live。第7阶段报告为切换前历史记录；当前结果见[改造报告](ai-model-loop-report.md)。

## 页面与能力

页面展示实际日期/上海时区/指标/后端对象ID、范围变更、固定执行阶段、本轮调用统计、关键指标、结果口径、事实证据、待核实事项、建议及未回答项。库存与商品数量保留各自单位，不在指标卡合计。长报告在有界区域滚动；对话记录可展开查看。

结果先暂存，只有收到匹配的成功done终态才发布；result之后出错、EOF或取消不会展示完整指标。部分数据以明确的证据不足澄清呈现，不能将缺失当零。错误时提供显式重试；重试重新鉴权与查询，不自动重发。发送期间同步禁用按钮；取消后以服务器持久状态为准。刷新按URL会话ID恢复历史与澄清，仍运行时显示刷新状态/取消，不能伪造节点续跑。客户端等待上限190秒，Java请求上限180秒；等待超时后停止接收并提示核对服务器状态。

| 能力 | 所需权限 | 口径/限制 |
|---|---|---|
| 销售总览、等长比较、趋势 | erp:sales:read | 含税已发货订单金额与去重订单数；全厂路径需要模型规划与证据核验 |
| 客户/商品排行、单对象汇总趋势 | erp:sales:read | 模型选择工具，代码核验并计算；名称歧义需确认后端ID |
| 当前库存、低库存 | wms:stock:read | 当前余额与最低库存阈值；非历史库存 |
| 已确认工单缺料 | mes:production:read及wms:stock:read | 确认快照需求减当前余额，需求未预留 |
| 待执行成品入库单 | wms:document:read | 待入库不计可用库存 |
| 利润/收入 | 不提供 | 先澄清，不能以销售额冒充 |

示例按当前用户权限筛选，单有生产读权限不提供缺料示例。后端每次调用仍执行真实权限/身份/对象范围检查；页面隐藏示例不是授权措施。

Java公开输出边界只转发允许事件字段，把阶段映射到固定中文状态，将内部表名/筛选表达式转成业务来源，过滤显式SQL语句、内部思考块、认证字段与密钥。模型思考不作为报告内容，原始工具认证、SQL、敏感联系人字段不展示。历史消息与标题在读取时也经过呈现过滤，不改写原始会话数据。过滤不是对任意自然语言敏感信息的完整分类；接口白名单与最小工具字段仍是主要边界。

执行统计包括工具分派尝试、实际模型HTTP请求和本轮耗时；提供方返回时才累计prompt_tokens/completion_tokens/total_tokens，并标明返回用量的响应数。某些调用未返回用量时只记录已知部分，不推算总token或成本。历史数据库不新增统计列，刷新后明确显示统计未保存；被取消且未到终态的执行统计可能缺失，报告不填零冒充测量。

## 隔离验收启动

先使用既有本地依赖服务，核对mini_mfg_test和Redis light-mfg:test:。不建库、不清库，不写开发库模拟会话或业务交易。依赖未安装时仅按项目锁文件安装；本轮没有升级。

```powershell
# 先在根目录构建及运行相关检查，成功后再启动JAR
./scripts/Test-AiEvaluation.ps1

# 终端一：只连接test profile，18081路由至18091
. ./scripts/Import-LocalEnvironment.ps1
. ./scripts/Import-AiEnvironment.ps1
& "$env:JAVA_HOME/bin/java.exe" -jar "$PWD/backend/target/light-manufacturing-server-0.1.0.jar" --spring.profiles.active=test --server.port=18081 --server.address=127.0.0.1 --mfg.ai.agent-url=http://127.0.0.1:18091

# 终端二：仅在已显式允许真实模型时执行，固定上海日期2026-10-20
./scripts/Start-AiAcceptanceAgent.ps1 -Live

# 终端三：Vue隔离5174，不能代理开发后端
./scripts/Start-Frontend.ps1 -Port 5174 -BackendTarget http://127.0.0.1:18081

# 终端四：准备独立SELECT基准及只读测试角色，执行真实浏览器
./scripts/Test-AiAcceptance.ps1 -Live

# frontend目录
npm run typecheck
npm run test:unit -- --run
npm run build
```

验收入口验证18081/18091进程归属、test profile、真实路由、数据库与Redis配置、Vue代理头和Live开关一致。使用已有测试库DM261020-RAW仓库、2026-10-01至02已发货数据及一张待领料工单；缺前提就失败，不静默造交易。只有mini_mfg_test可追加验收会话、只读角色和用户，保留现有数据。临时测试用户凭据只经忽略目录传给浏览器，完成后删除；报告不包含凭据。

默认Test-AiEvaluation仍完全不调用模型。未提供-Live的Start-AiAcceptanceAgent保留用于手工检查MODEL_NOT_CONFIGURED；Test-AiAcceptance现在在准备任何验收数据前拒绝未显式Live的运行，不能用无模型成功库存流程代替新架构验收。

`evaluation.acceptance_app`只用于测试：复用真实图与Java工具，不提供模拟业务数据。取消场景仅在专用前缀问题前注入4秒读取延迟，以稳定验证运行中取消。显式Live下“验收模型失败：”前缀仅替换为不存在的模型名并向实际提供方请求；下一轮普通“重试”恢复配置模型，用于核验失败恢复。该路径须明确标记故障注入，不能算模型响应性能。生产入口仍为app.main:app。浏览器失败、取消、未配置模型检查不代表验证过真实提供方故障。

## 五分钟演示

在独立测试页面 http://localhost:5174 登录。先确认页面身份和权限；不把开发页面当隔离演示。

1. **0:00–1:00：销售总览。** 显式Live开启后问“2026-10-01至2026-10-02全厂销售分析”，核对实际日期、含税已发货金额/订单、等长比较与证据。未开启模型时跳过成功演示，明确记录未验证，不展示静态报告替代。
2. **1:00–2:00：客户。** 问“2026-10-01至2026-10-02客户销售排行前5名”，从实际结果选客户ID，追问“客户ID 数字”。检查范围沿用与新查询；有重名则选择真实候选，不猜ID。
3. **2:00–3:00：库存和工单。** 问“仓库ID 实际ID 哪些物料库存不足”，再问“工单ID 实际ID 还缺哪些零部件”。核对查询时刻、当前库存/阈值/快照需求，说明待入库未加库存、多个工单未预留。
4. **3:00–4:00：澄清与权限。** 新会话问利润，展示口径澄清；再问“当前库存”，刷新后补仓库。切换只读库存账号，核对仅库存示例、库存可读、销售及写操作拒绝。
5. **4:00–5:00：失败与取消。** 用不存在的有效仓库ID展示安全失败和显式重试；测试入口用“验收取消：仓库ID 实际ID 当前库存”取消，刷新核对已取消。最后查看实际浏览器报告的成功率、耗时、调用数及未验证项。

演示结束只关闭自己启动的隔离进程，不停止既有开发/MySQL/Redis。当前能力不包括预测、利润核算、采购优化、自动业务写入、共享库完整多租户、长期记忆、并发工具原子快照或任意自然语言理解。
