# AI完善第2阶段：时间范围与指标澄清

日期：2026-10-20。沿用现有工具、会话、身份校验及依赖。时间计算在Python确定性代码中完成，模型只能使用已解析的startDate/endDate；改变日期的工具计划仍由既有校验拒绝。

## 日期语义

统一Asia/Shanghai，查询和报告采用左闭右开`[startDate,endDate)`。自然周从周一00:00开始，至下一周一00:00；完整自然月从当月1日至次月1日。相对日期在一次请求开始时读取一次上海日期，同一请求重规划不会跨午夜改区间。

以下示例固定“今天”为2026-10-20；内部边界均不包含结束日：

| 用户表达 | startDate | endDate | 含义 |
|---|---|---|---|
| 最近7天 | 2026-10-14 | 2026-10-21 | 含今天，1～366天 |
| 今天 | 2026-10-20 | 2026-10-21 | 今日截至数据读取时刻 |
| 昨天 | 2026-10-19 | 2026-10-20 | 完整上海自然日 |
| 本周 | 2026-10-19 | 2026-10-21 | 周一至今天，含今天 |
| 上周 | 2026-10-12 | 2026-10-19 | 上个完整周一至周日 |
| 本月 | 2026-10-01 | 2026-10-21 | 月初至今天，含今天；不把未来日期计入天数 |
| 上月 | 2026-09-01 | 2026-10-01 | 上个完整自然月 |
| 2026年10月 / 2026-10 | 2026-10-01 | 2026-10-21 | 指定当前月份也截到今天 |
| 2024年2月 / 2024-02 | 2024-02-01 | 2024-03-01 | 历史指定月份取完整自然月，含闰日 |
| 2025年12月31日至2026年1月2日 | 2025-12-31 | 2026-01-03 | 用户明确起止日期包含首尾日 |

明确日期支持YYYY-MM-DD（可不补零）及YYYY年M月D日，也可指定单日。指定月份要求年份（YYYY-MM或YYYY年M月），只有“2月”需补充年份。明确的未来日期/未来月份按用户给定范围查询已有记录，不预测；未发生业务通常为空。显式区间不因当前日期自动缩短。非法日期、倒序、多个冲突范围、跨度超过366天、年份低于1001或不完整区间均澄清，不退回旧区间。尚不支持任意自然语言日期、季度、同比或用户时区。

## 比较与指标

始终沿用Java现有“紧邻本期之前的等长天数”规则。若本期[start,end)为D天，则上期[start-D,start)。本月截至10月20日为20天，上期为[2026-09-11,2026-10-01)，不是整个9月；上月9月完整30天的上期为[2026-08-02,2026-09-01)，也不是自动按8月。报告展示实际本期、上期日期、结束日排除、Asia/Shanghai、比较规则和数据来源。

上期金额或订单数为零时，对应增长率显示“不可比（上期为零）”，包括本期也为零；不再用0.00%暗示存在可比基数。当前销售指标仍是按创建时间筛选**当前SHIPPED且未软删除订单的人民币含税订单金额、订单数**。不是会计收入、利润或某个历史时点的状态快照。今天的数据尚未结束，本期内订单状态仍按查询时刻读取。

## 澄清与恢复

- “最近”“经营怎么样”且会话没有范围时，先只问日期；补充日期后仍无指标时，再只问是否采用受支持的已发货销售金额/订单口径。未确认前不调用模型或业务工具。
- 用户问收入/营收，明确说明没有收入确认口径，询问是否改为含税已发货订单金额。利润与客户维度继续沿用原澄清分支。
- 最新回复给出的有效日期优先于原问题/历史区间；没有新日期时才复用已确定范围。日期无效时不会静默回退；需要用户重新给出有效区间。
- 指标澄清保存已经确定的日期；跨日回答指标问题不会重新解释先前的“本月”。成功会话仍存原有startDate/endDate/metric=sales，可继续使用已有范围和指标。
- “不可以”“不要分析销售额”等拒绝不视为同意。用户明确同意或改为销售口径后才继续。

HTTP路径、请求DTO、SSE事件、Cookie/CSRF、工厂/用户归属及工具能力令牌不变。澄清context增加的question值metric/revenue以及已有日期/metric字段均为内部受控上下文，客户端仍只提交message；没有HTTP测试日期或身份覆盖参数。

`agent/app/dates.py`用标准库ZoneInfo读取仓库固定的Shanghai TZif文件，支持Windows无系统IANA数据的环境和上海历史夏令时；文件来源、校验摘要与许可证位于`agent/app/timezone_data/`，依赖锁文件不变。Java历史日界仍独立使用ZoneId(Asia/Shanghai)，测试oracle也按IANA上海时区转换明细。
