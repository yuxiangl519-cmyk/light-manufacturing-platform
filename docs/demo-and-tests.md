## 后端验证矩阵

| 编号 | 用例 | 必须断言 |
| --- | --- | --- |
| B01 | 完整电脑案例 | 每阶段状态/余额/流水/库存单与上表一致；金额47000/9000 |
| B02 | 重复收货/领料/报工/入库/发货各两次 | 第二次replayed=true、operationId相同；余额和记录数均不增加 |
| B03 | 同单并发同动作（至少两个独立事务） | 只有一个成功命令和一次记账，另一请求重放或可重试冲突后重放 |
| B04 | 两张销售单并发各发6台，初始10台 | 一张成功、一张库存不足，余额4，只有一张已执行出库，任何时刻无负值 |
| B05 | 工单领料缺1条内存 | 整单失败；其余五种余额不变；无出库/流水/成功命令；工单仍待领料 |
| B06 | 余额更新后、流水写入前注入异常 | 所有余额、单据、命令、成功审计回滚，无半单 |
| B07 | 确认工单后BOM内存从2改3 | 老工单仍耗20条；新工单耗30条；各bomRevision/快照正确 |
| B08 | BOM更新与确认并发 | 工单只得到完整旧版或新版，不能混合组件/版本 |
| B09 | 非整数/越界输入 | "1.5"/"1e2"/"-1"/"0"/数字JSON/13位数量拒绝；阈值0接受；乘法或金额溢出拒绝 |
| B10 | 金额精度 | 单价0.10×3=0.30；多行精确汇总；超过两位小数输入拒绝；响应固定两位 |
| B11 | 非法状态及编辑 | 未确认收货、未领料报工、非生产入库执行、确认后PUT/删除/取消返回409且无变化 |
| B12 | 首次余额行并发创建 | 同维度两次合法入库后仅一余额行，总量正确，无丢更新 |
| B13 | 来源和数据库约束 | 同来源同kind不能重复；孤儿FK失败；负余额CHECK失败；每库存单行恰好一流水 |
| B14 | 草稿取消/删除 | CANCELLED可查不可执行；逻辑删除404；历史编号不复用 |
| B15 | 资料限制 | 采购不能选成品、销售不能选原料、重复明细失败；停用阻止新确认，已确认业务仍可完成 |
| B16 | 对账 | 每仓库物料余额=流水净和；所有流水前后余额连续，来源链完整 |
| B17 | 版本和事务释放 | 旧version首次动作409；成功后旧version重试仍重放；失败后无持续占锁，下一合法事务可完成 |

数据库集成测试使用明确批准的 `mini_mfg_test`/MySQL8.4.7，每例隔离自身数据；并发线程各用独立连接和事务，测试方法不套吞没提交的外层事务。使用latch/barrier控制竞争，等待有超时，不用碰运气的sleep。禁止访问参考库、使用create-drop或全库clean。测试数据可在专用测试库按本次fixture外键顺序清理，前置核对库名，不能触及共享资料。

## 作品说明文案

轻量制造管理平台是面向电脑组装工厂的个人作品，以标准办公台式机为演示产品，将零部件采购、BOM用料、整机生产、仓储记账与销售发货串成可追踪的闭环。项目采用Java17/Spring Boot与Vue3，在模块化单体中通过MySQL本地事务、来源唯一约束和并发锁保证库存一致性，并以角色权限控制后端业务操作。第一版聚焦一次性整单操作，便于本地演示和后续学习。

当前作品已完成后端认证/系统、资料/BOM、冻结快照及采购/生产/仓储/销售最简闭环，通过57项测试。报工后库存不变、执行成品入库才加库存，重复命令与并发出库由MySQL事务保证。Vue页面、工作台及浏览器展示仍待后续；对外说明不得称已有前端成品。
