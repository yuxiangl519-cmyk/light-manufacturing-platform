# 需求规范

版本：设计基线 1.0，2026-10-17（Asia/Shanghai）。第2阶段已实现后端基础、认证和系统管理；其余范围仍是后续业务设计，实测见stage2-verification.md。

## 目标与场景

轻量制造管理平台是可在本机运行和演示的个人作品，集成 ERP、MES、WMS，采用模块化单体、前后端分离。用户已再次确认沿用电脑组装工厂场景，后续提示模板中的“小风扇”不作为需求。覆盖零部件采购、整机组装、仓储和销售。

## 数量、金额和资料规则

- 统一物料表，类型创建后不可改；被引用的编码、单位不可改，名称可改，历史单据保存名称/单位快照。资料不提供硬删除，只停用。停用禁止新单据引用、草稿确认；已确认单据使用确认快照继续执行，避免无法完成。
- 采购仅原料，销售仅成品。每张采购/销售单一个仓库，明细至少 1 条、最多 100 条，同物料不可重复。工单明确一个领料仓库与一个成品入库仓库，可以相同。
- 数量使用 BigDecimal，数据库 DECIMAL(12,0)，输入规范为不带符号、小数点或指数的正整数字符串，范围 1～999999999999。库存余额、预警阈值允许 0。BOM 单耗也为正整数；工单数量乘单耗溢出须在确认前拒绝。
- 金额与单价为 BigDecimal/DECIMAL(18,2)，人民币，无税率、折扣、运费、币种换算。单价允许 0，输入最多两位小数，超过两位拒绝，标准输出两位。计算使用 HALF_UP 保留两位；行金额=数量×单价，单据金额=各行金额之和；服务端计算并检查溢出，客户端金额仅预览。
- 所有时间按 UTC 存储、ISO 8601 带时区传输，界面按 Asia/Shanghai 展示。

## 状态与动作（规范源）

| 单据 | 动作 | 前置 → 后置 | 库存及联动 |
| --- | --- | --- | --- |
| 采购 | confirm | DRAFT → CONFIRMED | 无库存变化，冻结明细及金额 |
| 采购 | receive | CONFIRMED → RECEIVED | 全量加原料；生成已执行 PURCHASE_RECEIPT 入库单及流水 |
| 工单 | confirm | DRAFT → READY_TO_ISSUE | 保存 BOM 编号、版本及全部组件用量快照 |
| 工单 | issue | READY_TO_ISSUE → IN_PRODUCTION | 全量扣原料；生成已执行 PRODUCTION_ISSUE 出库单及流水 |
| 工单 | report | IN_PRODUCTION → PENDING_INBOUND | 按计划数量记录一次报工；生成 PENDING 的 PRODUCTION_RECEIPT 生产入库单；库存不变 |
| 生产入库单 | execute | PENDING → EXECUTED | 全量加成品；关联工单 PENDING_INBOUND → COMPLETED |
| 销售 | confirm | DRAFT → CONFIRMED | 无库存变化，冻结明细及金额 |
| 销售 | ship | CONFIRMED → SHIPPED | 全量扣成品；生成已执行 SALES_SHIPMENT 出库单及流水 |
| 采购/工单/销售 | cancel | DRAFT → CANCELLED | 无库存变化，终态 |

草稿可整单修改、删除或取消；删除为逻辑删除，只允许无成功命令记录的草稿。CANCELLED 是保留记录的终态，不可恢复。已确认不编辑、不取消、不反冲；不提供回退状态、直接改状态接口。收货/领料/报工/入库/发货不接收实际数量参数，完全使用冻结计划，避免分批或超额操作。

## 库存一致性

1. MySQL 是唯一事实来源；Redis 不存库存、不承担库存锁。
2. 唯一余额维度为 warehouseId + materialId，无在制品库存、库存预留或可用量/实物量双账。
3. 每次动作在单个本地事务内提交状态、余额、流水、出入库记录及成功命令记录。任一物料不足或任一步失败则整单回滚。
4. 锁单据后按仓库和物料 ID 升序锁余额，先校验整单再记账；余额非负和来源唯一作为数据库兜底。
5. 同一单据同一动作只允许一个成功结果。重试命中成功命令记录则返回 replayed=true，不重复扣加或生成下游单据；非法首次跳步返回 409。
6. 流水不可改删，记录来源业务单据、库存单据、前后余额、操作者和时间。库存页面没有手工新增/修改按钮或接口。

## 权限与安全

用户—角色—权限，多角色权限取并集。内置 ADMIN 管理员、OPERATOR 业务操作员、VIEWER 只读用户。权限点由代码固定；管理员可在页面分配角色权限和用户角色，不支持表达式编辑和数据权限。

所有业务接口后端鉴权，前端隐藏按钮只改善体验。所有登录用户可访问自己的会话；系统管理和操作日志另需系统权限。保持至少一个启用且有 user/role 管理权限的 ADMIN 用户，内置 ADMIN 全权限不可削减；可调整其成员，不能删除内置角色。

Redis 用于登录会话及登录失败限流；会话 30 分钟空闲失效；Cookie HttpOnly、SameSite=Lax，本地 HTTP 可不设 Secure，上线 HTTPS 必设。使用 CSRF token，登录也校验 CSRF。密码用 BCrypt，不存明文、不提供公共注册。

## 工作台口径

- 待办：待收货采购、待领料工单、生产中待报工工单、待生产入库单、待发货销售单，分别按动作权限过滤入口与数量。
- 金额按单据创建时间选择统计区间（上海日期转 UTC 半开区间），统计已确认及后续状态的采购/销售总额；草稿/取消/删除不计入。另显示实际已收货采购金额、已发货销售金额；不称收入、成本或利润。
- 生产进度为状态分布及阶段步骤，无分批完成百分比；完成数量仅已完成工单计划量之和。
- 预警：启用仓库×启用物料中，余额小于物料 minStock；缺失余额按 0。阈值为 0 时不预警。

## 验收

详见 [演示与测试设计](demo-and-tests.md)。核心案例从零库存采购五类各 20、内存 40，生产 10 台，领料后五类各 10/内存 20；报工成品仍 0；执行入库后 10；销售发货 3 后成品 7。还须通过并发、重复、回滚、BOM 快照、精度、越权及 CSRF 验证。

## 不做事项

不做自定义选配、兼容性校验、多层 BOM、排产、工序报工、分批收发/领报/入库、复杂审批、序列号、批次追溯、质检、退货、盘点、库存调拨、库存调整、在制品、售后、维修、保修、财务核算、自定义权限表达式和复杂数据权限。不引入微服务、消息队列、工作流引擎或分布式事务。

## AI时间与指标澄清（2026-10-20）

支持最近N天、今天/昨天、周一为起点的本周/上周、本月/上月、明确起止日及带年份的指定月份。内部上海日期左闭右开；本周/本月截至今天，相邻上期始终等长天数。未确定日期/指标时一次只问一个关键问题；收入/利润不得由含税订单金额替代。无基数不输出误导性增长率。边界、恢复与实测见[时间范围说明](ai-time-ranges.md)。
