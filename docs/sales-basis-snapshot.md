# 销售日期口径与一致读取

2026-10-23。本轮保留默认接口，同时补充实际发货日期。

## 日期归属

- `dateBasis=created_at`（缺省）：按订单创建时间筛选当前SHIPPED、未删除销售单。它回答“这批创建的订单现在已发货多少”，之后发货会改变旧期结果。
- `dateBasis=shipped_at`：使用既有真实发货时刻；回答“这个月实际发货销售情况/发货金额”。缺失发货时刻不拿创建时刻代替。
- 两种都为人民币含税销售单金额，不是收入、利润或到账金额。客户取单头、商品取明细；订单去重、单位分开。
- Asia/Shanghai，结束日排除，最多366天；相邻等天数比较。原日期解析、零基数与少样本规则继续使用。
- Java只接受以上枚举，参数化绑定日期/ID；只从白名单选择固定时间列。Python执行器从用户明确表述和已确认上下文注入口径，模型工具参数不接受列名。
- 用户未指定时保持兼容默认，并在报告显示实际口径；用户要求两种混合或按付款/确认等未支持日期时澄清，不暗中更换定义。
- 新会话首次绑定销售域、刷新和“那上个月呢”均保留口径；显式“改按创建时间”覆盖旧值。

## 原子读取边界

ERP公开 `SalesSnapshotService` 使用短 `REQUIRES_NEW + REPEATABLE_READ` 只读事务，30秒上限；各SQL仍限5秒与返回行数。

总体的本期/等长上期汇总、逐日趋势及客户/商品前20名在同一InnoDB读取视图内获得，再返回同一 `snapshotId/snapshotScope/asOf`。Gateway在当前短期grant中按起止日期+口径缓存有界bundle，不在不同HTTP请求之间持有数据库事务，排行按请求limit裁剪。每次工具调用仍检查当前用户、权限、归属、运行状态和调用上限；缓存不充当授权。

指定客户或商品的summary/trend在另一个短一致事务中获取并共用标识。名称解析只用于对象确认，不与候选查询保证同一业务快照。不同对象、不同期间或不同任务也不声称共享同一快照；库存/工单数据仍有各自读取时刻。

真实HTTP适配器拒收缺失快照或口径不匹配的销售响应；EvidenceEngine拒绝不同快照ID、单边缺失ID和不同口径。保留旧格式仅供原组件与确定性测试兼容，必须说明没有原子快照保证，不能冒充真实模型或真实一致性验证。

## 验证

真实MySQL8测试将发货时间与创建时间放入不同时段，独立断言本期金额、天趋势、边界及默认接口。快照测试在读取汇总后，让另一线程在独立连接提交金额变更：趋势和排行仍为原金额，新一次snapshot读取新金额。它验证读取视图而非仅比较时间戳。其他检查见 [本轮交付](hardening-report.md)。

## 部署限制

当前仍是单工厂、单应用实例展示；授权票据、运行句柄及bundle位于进程内。MySQL持久化会话、额度与调用记录，异常重启后回收过期RUNNING任务，允许重新发起；不从工具执行中间点恢复。未引入LangGraph持久化Checkpointer，不宣称高可用、共享库SaaS多租户或任意节点恢复。
